********************************
Combined workflow
********************************

The combined workflow joins the bottom-up buildings and vehicles models with
the top-down plastics, steel, and cement models. It is implemented in
``eumfa_combined.py``. The script maps bottom-up results to the dimensions of
each material model, calculates the residual top-down demand, and creates the
future final-demand inputs used by the material models.

Selecting models
================

Set the flags near the top of ``eumfa_combined.py`` before running the script:

* ``COMBINE_PLASTICS`` enables the plastics coupling.
* ``COMBINE_STEEL`` enables the steel coupling.
* ``COMBINE_CEMENT`` enables the cement coupling.
* ``DOWNSTREAM_ONLY`` runs a material future model from an already generated
  combined input instead of recalculating the bottom-up and residual-demand
  stages.

Run the selected workflow from the repository root:

.. code-block:: console

   python eumfa_combined.py

The baseline configuration has been verified for the combined vehicles,
plastics, and steel workflow. Buildings or cement can be enabled through their
respective flags when their required input data are available.

Input and output paths
======================

Model YAML files may declare ``input_data_path`` and ``output_path``. The
runner honors these explicit paths. This is required for combined models,
because their generated inputs live in dedicated working directories rather
than in the default directory derived from model class and scenario name.

Generated intermediate files are written below the relevant model input tree.
They are run artifacts, not manually maintained source data. Important examples
are:

* ``data/fd-sv-gr_plastics/input/datasets/FinalDemand.csv``;
* ``data/fd-sv-gr_plastics/input/datasets/total_future_demand.csv``;
* ``data/fd-sv-gr_plastics/input/datasets/vehicles_plastics_reuse.csv``;
* ``data/baseline_fd-sv-gr_steel/input/datasets/FinalDemand.csv``.

Plastics coupling
=================

Before a full plastics coupling run, the workflow seeds
``data/fd-sv-gr_plastics/input`` from the baseline source input tree. This
ensures that dimensions and unchanged parameters needed by the future model are
available alongside the generated final-demand data.

The plastics historic model uses ``config/plastics_baseline_pd.yml`` and writes
historic flow exports below ``data/baseline_pd_plastics/output``. The future
model uses ``config/plastics_combined_future.yml`` and reads the generated
``FinalDemand.csv``. Historic and future flow exports are then joined below
``data/combined_plastics/output/flows``.

With ``DOWNSTREAM_ONLY = True``, plastics runs only the future model defined in
``config/plastics_combined_future.yml``. A prior full combined plastics run
must therefore have generated its ``FinalDemand.csv``.

Vehicle plastics reuse
======================

Vehicle plastics reuse is optional. The vehicle configuration uses the
``plastics_reuse`` scenario selector (``B``, ``C``, or ``A``). For a selected
variant, the workflow looks for the matching dataset:

.. code-block:: text

   data/baseline_vehicles/input/datasets/vehicle_plastics_element_reuse_<variant>.csv

If the dataset is absent, the run emits a warning and continues with zero
plastics reuse. This rule applies consistently to all three variants; therefore
the baseline workflow remains runnable without a plastics reuse dataset.

When a dataset is present, the vehicle model calculates a reuse flow from the
vehicle plastics end-of-life flow. It reduces new plastics demand in the
vehicle model and exports the explicit internal reuse flow. The combined
workflow maps this reuse flow to plastics dimensions and stores it as
``vehicles_plastics_reuse.csv``. Because future plastics end-of-life is
calculated within the combined plastics model rather than supplied directly by
the vehicle model, the mapped reuse amount is subtracted from the future waste
collection flow and propagated proportionally through the subsequent sorting,
recycling, recyclate, and losses flows.

The zero-reuse fallback and the full baseline combined workflow have been
verified. A non-zero plastics reuse scenario still requires a supplied reuse
dataset and scenario-specific result validation.

Steel and cement prerequisites
===============================

Steel downstream-only runs use ``config/steel_combined_future.yml`` and require
the steel ``FinalDemand.csv`` produced by a prior full combined steel run.
The configured steel reuse input is read from ``SteelReuse.csv`` in the steel
dataset directory. The current combined orchestration does not yet generate
this input from the vehicle steel reuse flow.

The cement stock and flows models use future demand generated by the combined
cement workflow. Run the applicable combined cement workflow first when those
future-demand input files do not yet exist.
